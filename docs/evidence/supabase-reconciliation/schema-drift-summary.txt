5. DETECTED REMOTE HOT-FIX DRIFT (1 OBJECT)
--------------------------------------------------------------------------------
Object Name: public.digest(bytea, text)
Definition:
  CREATE OR REPLACE FUNCTION public.digest(bytea, text)
  RETURNS bytea
  LANGUAGE sql
  IMMUTABLE PARALLEL SAFE
  AS $$
    SELECT extensions.digest($1, $2);
  $$;

Root Cause Analysis:
In 20260911000001_production_contract_closure.sql, rpc_execute_idempotent_mutation
enforces strict isolation by declaring:
  SET search_path = public, pg_temp;
Inside the function body, it computes:
  v_payload_hash := encode(digest(convert_to(COALESCE(p_payload, '{}'::jsonb)::text, 'UTF8'), 'sha256'), 'hex');
In Supabase-managed PostgreSQL, the "pgcrypto" extension places cryptographic
functions (including digest) in the "extensions" schema. Because "extensions" is
intentionally excluded from search_path for SQL injection / schema-poisoning defense,
calling digest() directly inside rpc_execute_idempotent_mutation failed with:
  ERROR 42883: function digest(bytea, unknown) does not exist.
During the previous live-verification session, public.digest(bytea, text) was created
via direct remote SQL on the live database to resolve the runtime error without
modifying the frozen migration file.

However, because this was performed directly on the remote database, Git did not
contain a migration creating public.digest. Thus, a clean deployment on a fresh
database would fail to execute rpc_execute_idempotent_mutation.

Resolution:
Create a canonical forward migration:
  20260912000001_reconcile_remote_schema_drift.sql
This migration:
1. Formally defines public.digest(bytea, text) in repository migration history.
2. Restricts function execution privileges (REVOKE FROM PUBLIC, anon; GRANT TO authenticated, service_role).
3. Pushes the migration to the remote database to register version 20260912000001 in schema_migrations.
4. Leaves 100% parity between Git history and live PostgreSQL definitions.
